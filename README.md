# 片刻 · 明信片工作室

把喜欢的图片变成可印刷的明信片。手机和电脑均可通过浏览器使用，图片、地址和排版数据在设备本地处理。

在线地址：https://YushenDu224.github.io/postcard-studio/

## 使用

1. 选择 JPG、PNG 或 WebP 图片，或试用内置原创示例。
2. 输入成品宽高和单位，设置输出精度、四边裁切余量与文字安全距离。
3. 正面选择裁剪铺满或完整留白；拖动图片、调整缩放和边框。
4. 背面选择模板，填写介绍、署名、作品信息，以及可选地址和 Postcrossing ID。
5. 下载正面、背面 PNG 或双页 PDF。PDF 第一页正面，第二页背面；辅助线不印入文件。
6. 按 100% 实际尺寸印刷。双面翻转方向由打印机和进纸方式决定，先用一张测试。

“保存项目”导出带原图和排版信息的 `.postcard.json` 文件。另一台设备通过“打开项目”接续编辑。项目可能含地址和签名，请妥善保管。

## 隐私与离线

- 无账号、无在线 AI、无广告或应用遥测，无图片或地址上传功能。
- 页面依赖、图标和示例均随项目提供；不加载第三方 CDN、在线字体或统计脚本。
- 首次访问需要联网获取应用；资源缓存成功后支持离线重开。
- 默认仅保留本次页面内容。本机自动保存需要主动勾选，可随时清除草稿。
- 浏览器存储可能被清理，长期保存请导出项目文件。
- GitHub Pages 在访问时可能记录 IP 等托管日志；应用内素材不发送到 GitHub。
- 导出图片重新从画布编码，不复制原图的 EXIF/GPS 信息；保存项目包含未经改写的原图，可能含原始元数据。
- 本地数据库和项目文件未加密。

## 导出范围

PNG 从原图按目标像素数生成，并写入对应 pHYs 密度信息。PDF 为高精度栅格图像 PDF，包含两页、实际物理尺寸以及 TrimBox / BleedBox；文字已渲染成像素，不依赖接收方字体。

当前输出使用 RGB，未实现 ICC 色彩管理或 PDF/X 合规验证，也不宣称已完成 CMYK 转换。印刷店若要求这些规格，需要后续增加独立的本地印前处理模块。

原图清晰度与输出像素数量分别计算；高精度导出不会补回原图缺失的细节。单面导出限制为 4000 万像素，防止移动设备内存耗尽。实际支持能力仍取决于设备。

## 架构

```text
core/                    独立 C++20 数值核心，无 UI 依赖
docs/core-adapter.js      稳定处理接口：WASM 实现 / 本地预览兼容实现
docs/model.js            项目模型、验证与版本
docs/render.js           根据布局模型绘制预览和印刷输出
docs/export.js           PNG 密度与双面 PDF 文件生成
docs/storage.js          浏览器 IndexedDB 本机草稿
docs/app.js              输入事件与界面编排
tests/                   数值、导出文件结构和 C++ 核心检查
.github/workflows/       测试、C++ → WebAssembly 编译与 Pages 发布
```

网页不展示源代码或语言信息。发布后的尺寸、像素与清晰度计算使用 C++ 编译的 WebAssembly。浏览器选图、编码与文件下载由独立网页模块承担。SQLite 留给后续安装式应用，网页首版使用浏览器 IndexedDB，避免引入不必要的数据库运行库。

## 开发与部署

需要 Node.js 18+，没有 npm 运行依赖：

```sh
npm start
npm test
```

预览：http://127.0.0.1:8765 。未编译 WASM 时使用相同接口的 JS 数值实现。

原生 C++ 检查：

```sh
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

GitHub Pages 的 Source 选择 GitHub Actions；推送 main 后自动测试、用官方 Emscripten 编译 C++、上传 docs 静态产物并部署。网页界面和 C++ 核心可独立迭代，适配层保持稳定接口。

技术方案.md 记录最初安装式应用方向；本 README 描述当前实际交付的静态网页版本。
